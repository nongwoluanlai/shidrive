# v0.3.6 OAuth 共享开放权限合并说明

基线：`nongwoluanlai/shidrive` **v0.3.6**（`2dd0e5c99cd2feb3b6f22002012da26d26058f6e`）。该改动不改产品版本号、不改 SQLite schema，也不改变 Passcode 接入格式。

## 使用方式

1. 在「设置 → 外部编程接入 → 开放目录与上下文」添加项目目录，按需绑定上下文、启用文件写入/命令执行；命令执行另需开启全局开关。
2. 启动外部编程服务，把页面显示的 `…/mcp` 地址交给支持 MCP OAuth 的客户端。OAuth `.well-known`、`/register`、`/authorize`、`/token` 等端点仍自动提供，**设置页不再展示元数据地址**。
3. 客户端发起 OAuth 后，使驾会唤出主窗口并显示全局审批窗，**无需先打开设置页**；关掉审批窗不会拒绝请求，标题栏的「待授权」按钮可重开。前端启动/重开或漏收事件时会向后端查询未过期请求；请求 10 分钟内有效。
4. 审批显示客户端、回调地址、所请求的 scope、当前开放目录与上下文。批准**不会再创建单项目授权或新 Passcode**；新 OAuth 令牌可访问所有当前未暂停/撤销的开放授权，后续增减/暂停会对它实时生效。实际能力 = OAuth 请求 scope ∩ 对应开放授权的权限；执行命令还必须开启全局开关。客户端不指定 scope 时，桌面端会要求确认全部支持的 scope；显式请求部分 scope 不会自动提升。
5. 多目录 OAuth 客户端先调用 `pc.access.list` 获取 `grant_id`、目录、可访问的 `context_id` 和有效权限；文件/命令工具指定 `grant_id`，或者提供可归属的绝对路径（只有一个可用授权时可省略）；上下文工具**必须**指定已开放的 `context_id`。同一文件操作不能跨多个授权根目录；批量写入指定单条 `grant_id`。目录越界、只读限制、上下文隔离以及执行双开关由后端逐次检查。
6. 「OAuth 客户端」表保留客户端、权限、最近使用和吊销。吊销使对应访问令牌和刷新令牌立即失效；有效期规则保留（access 1 小时、refresh 30 天），仅从界面隐藏。v0.3.6 原有单项目 OAuth 令牌保持原项目范围，重新发起 OAuth 才使用共享开放权限。

> **安全提醒**：共享 OAuth 允许访问**以后新开放**的目录（受既有 scope 限制），批准前请确认客户端可信；若只希望访问某个目录，继续使用该行的 Passcode，或暂停其它目录。命令执行不是文件沙箱，开启后会以本机用户权限运行。隧道/监听服务暴露公网时应谨慎设置。

## 回归检查

- `cd app && pnpm install && pnpm check && pnpm build`
- Windows：`cd app/src-tauri && cargo test --locked --bin shidrive`；发布时 `cd app && pnpm tauri build` 生成 NSIS 安装包。
- 手动联调：不打开设置页发起 `/authorize` → 全局审批出现；关闭后从标题栏重开；打开两个目录和上下文，批准一次后 `pc.access.list` 应列出两条；分别调用文件与上下文工具；暂停/恢复/删除某条授权、关闭全局执行开关，检查工具列表和拒绝行为；吊销令牌后检查 access/refresh 均不能再使用；旧 Passcode 与旧 OAuth 令牌仍受原范围限制。

源码测试覆盖待授权快照/过期/重复审批、签发与轮换/吊销/旧令牌兼容、开放目录动态变更、scope 与上下文约束、目录前缀与存在性探测。该仓库的 `setup.rs` 与卸载工具含 Windows-only 命令扩展，直接在 Linux 执行完整 `cargo check` 会因其原有的 `.no_window()` / `.creation_flags()` 报错；本次在 Linux 上通过**临时移除**这些基线 Windows-only 调用运行了 Rust 单测，临时改动未包含在合并包中。
